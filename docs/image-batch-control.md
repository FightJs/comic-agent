# 图像批次暂停、有效预算与检查点

2026-11-06增量。范围为现有固定图像批次及其视觉检查/一轮返修；不是所有文本、图谱任务的全局预算。当前测试与独立页面状态以`docs/pi-progress.md`为准。

## 操作

运行中“暂停新派发”立即禁止后续生成、视觉与返修请求，进入“等待在途返回”。已提交的请求仍保留原返回、候选或报告；暂停不等于取消费用。收尾结束后显示“已暂停”，保存本批任务/调用/视觉/返修引用的检查点，再勾选核对并“明确恢复原批次”。暂停不要求先处理本地草稿，继续仍会拦截根图/返修图/输入的未保存草稿与版本变化。

暂停期间不得提前恢复另起同批worker；因异常中断但旧worker仍在收尾时也不能恢复，避免时钟与派发重叠。全局同时最多8个图像批次，暂停收尾及到限收尾的实际worker也计入；真正暂停后释放运行容量。图像/视觉单次调用容量仍分别1。

取消则放弃后续操作，沿原逻辑阻止在途新候选登记，但保全供应商返回；取消的批次不直接恢复。暂停会保留在途候选，适合稍后继续，二者语义不同。

## 时间预算

每个新批次固定四小时目标、七小时有效运行硬限，持续跨暂停/恢复/重启累计，不由recover清零。达到目标提醒；达到硬限不再派发任何新图像/视觉/返修，在途返回继续保全，因收尾可能显示超过七小时。不能用恢复原批次扩大硬限，需另行明确新范围与授权，未决调用仍不能重发。

正常运行用单调时钟计量；暂停后、等待用户核对的needs_attention、预览、正常关闭后的离线时段不计，暂停请求到在途收尾结束的时间计入。内部等待模型/容量期间仍属于活动运行。UI显示：

- **已计入预算**：`effective_seconds`，包含已确认运行与异常未知上界，不是未知区段的实测耗时。
- **已确认**：`confirmed_seconds`，单调时钟确认部分。
- **异常未观测上界**：`uncertain_seconds`，独立标明，可能包括离线等待，不能假装测量了这些时间。

宿主活动时每秒更新计时检查点，并预留短时间额度；正常收尾按真实单调耗时结算。异常退出无法知道最后实际存活时刻，恢复按最后检查点至当前启动的保守时间上界占用未观测额度，至少不退还原预留；只占用到本批硬限，不将离线时段谎报为实际工作。时钟回退或缺少旧锚点无法建立上界时保守耗尽剩余额度。**代价：长时间异常退出后，即使实际工作很短，也可能提前耗尽预算。** 这是防止故障/重启自动刷新硬限的处理，不是费用扣款或精确工时结论。

没有旧计时账本的历史批次明确显示“历史时长未知”，首次明确继续后增量记账；不追溯伪造历史用时，也不把后来新增的七小时控制宣称覆盖旧历史。此标记持续保留，不因继续成功而消失。

## 宿主边界

新增`backend/image_batch_control.py`，数据增量放原image_batches.payload.runtime。原调用、回执、候选与采用仍在原表，不另建第二套付费账本。检查点保存各格status/call_id/output_id和后处理review/repair引用，恢复以这些原账本当前状态为准，不能只依赖UI百分比或旧快照。

派发与实际提交前都检查状态和剩余预算，覆盖普通图、真实前图绑定、视觉容量等待和返修容量等待。暂停造成的未提交图像任务保留preview，可继续原call；不会误标永久blocked。计时内存失联或刷新过期会停止派发并要求明确恢复。DB刷新回滚保留最后已提交的时钟观察；恢复不会以未提交的内存状态抹掉预算。重启首先保全未知状态，不自动调用模型。

这些能力不等于完整阶段六：文本2/图像1/视觉1的统一可配置容量、token/金额预算、所有Pi任务检查点/20轮50工具后的完整暂停恢复、压缩保真与已确认无图技术重试仍须继续实现/验收。
