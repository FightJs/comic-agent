# 画风/资产AI生图方案

2026-11-06：代码与隔离自动化已接，独立页面复审通过98/100（仅本轮范围）。对应Pi计划阶段三“生成请求”和用户画风资产自然语言需求，不扩展图片工作区高级编辑。

协议：新style/asset讨论显式开放propose_image，旧tools=true仍只含既有两个工具，旧检查点不扩权。模型只提出title/prompt、可选附加目标和固定参考；不允许APIkey、模型参数、审核或图片URL。目标限本次明确附加的本阶段固定版本；其他参考限当前项目已冻结且已采用审核通过的图片。资产还固定已确认画风。已读mock继续继承。

宿主保存独立不可变方案，不改记录、不付费。完整讨论完成后用户在方案中查看具体提示词/目标/参考，点击创建预览；再复用ImageGeneration查看固定型号/输入并明确确认1张。预览用固定幂等token，原输入/参考/画风选择变化拒绝，重复点击不重复任务。生成仍为未采用候选，不冒充已观察像素或人审通过。旧运行无新工具不自动升级。

## 操作

1. 在画风或资产阶段打开AI助手，重生成时先将目标附加到本次固定资料，说明希望改变/保留的内容。新建可以无目标；资产需先确认当前已采用、审核通过的实际画风图。
2. AI回复下出现“生图方案”。展开核对完整提示词、目标版本及图片参考；拒绝不修改原图。已有未保存目标/参考草稿会阻止预览。
3. 回复完整完成后点击“创建生图预览”，打开原图像任务面板。预览不发送供应商；型号、实际提示词、参考和目标都在该面板固定。再点击“确认并生成1张”才提交图像调用，费用未知。
4. 如资产详情发生保存冲突，可选择“保留编辑并读取最新版本号”后核对保存，或“放弃草稿并读取最新内容”。放弃只读取服务器，不写入；读取失败或期间编辑变化会保留草稿。旧方案仍按原固定版本检查，不自动更新。
5. 返回图先保存为独立未采用候选，原图和人工审核不变。关闭内层回到当前方案按钮；刷新后可从同一方案打开原任务，重复点击不会新建付费请求。预览丢弃后需另提新方案，不自动重发。

## 固定输入与权限

目标仅限本轮明确附加的同阶段style/asset固定版本。参考须在冻结目录中且为当前已采用、审核通过的实际图；资产自动绑定本轮已确认画风，连同底图最多16份。预览与调用前再次核对版本/采用/审核/选择；已变化拒绝，不偷偷更新到最新图。模型不能指定APIkey、供应商地址、模型或任意文件路径。

方案是独立agent_image_plans记录，prompt和参考不接受修改；新要求另提新方案。只有原run完整completed可预览；额度暂停、取消、中断及旧工具运行不能放行。预览与已配置image_jobs服务共享幂等与未决调用保护，不另建供应商执行器。项目作用域由宿主固定。

新stage运行以显式allowed_tools开放propose_image；Node tools=true仍保持旧两工具，旧检查点hash与工具权限不变。新工具也计入持久50工具额度，恢复沿同一权限数组。

同项目/同会话历史已知mock及附加模拟依赖会继承到新方案；方案提出后再读mock，会标记当前run已存方案/文字候选和manifest，不能洗白。模拟来源不代表真实服务免费：确认生成仍调用已配置图像模型，结果保留来源标记。

## API与保存

- 模型工具：propose_image({title,prompt,target_id?,category?,references?})，references为固定图片记录id；不接受模型配置。
- GET /api/projects/{pid}/agent/image-plans/{id} 查看方案。
- POST .../{id}/preview：完整回复后明确创建预览，固定token重复返回原job。
- POST .../{id}/reject：仅未建立图像任务时拒绝；已建任务请在图像面板丢弃/核对。

SQLite方案随data备份；不存配置密钥。agent run返回image_plans摘要。原文档修改候选与图像方案分别存储，方案不会直接写style/asset记录。

## 验证与限制

backend/tests/test_agent_image_plans.py含两种实际Pi SDK→本机文本替身闭环：直接模拟依赖，以及先ai方案后读取mock，均只存方案；人工预览后再确认才进入本机图像替身，原目标v1/未采用候选及mock来源保持。覆盖旧工具拒绝、非法字段、过期目标、目标同版本审核、自动画风撤回、预览幂等及项目隔离。Node协议实测旧true两工具、显式三工具。独立代码审核发现的来源与target审核缺口已补回归并复审通过。

页面报告docs/pi-image-plan-ui-review.md，以实测结论为准；数量与运行记录docs/pi-progress.md。文字助手仍不读图片像素；方案不能代替视觉判断。图片工作区的高级批注/蒙版/精确选段、自然语言连续批次计划仍未由此实现，真实供应商效果/费用及长篇语义质量未实测。


同组三套二维画风可通过propose_style_tests基于固定原著证据与已审核细纲一次提出，宿主统一共有内容并保留三个方向，仍逐套预览、明确授权和人工采用；操作与版本/来源边界见[三套画风测试](style-tests.md)。它不是原propose_image的隐式扩权，旧检查点不自动开放。
