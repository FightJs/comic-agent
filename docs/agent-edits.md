# AI 修改候选与采用

当前状态（2026-11-05）：阶段助手已支持真实模型工具链产生结构化修改候选，独立存储，人工核对后建立新版本。骨架/细纲、范围脚本及生图包文本生产另见`docs/document-generation.md`、`docs/production-text.md`；图片生产仍为模拟。

## 使用

1. 在当前阶段打开AI助手，新建讨论，勾选需要修改的本阶段资料。可先询问原著、规则、当前内容。
2. 说明修改要求，例如“请优化这几格台词并提出修改候选”。只写普通答复不代表成品已改；AI必须通过工具提交结构化候选。
3. 打开“查看修改候选”，逐项核对修改前和建议内容，以及目标话格/版本。
4. 点击“采用这些修改”才写入新版本；也可拒绝，拒绝不影响原稿。一个候选中的多个修改作为一组核对；任何目标版本冲突时整组不写入。
5. 采用后附加资料仍指向旧固定版本。可明确点击“更新附加资料到已保存最新版本”，保留同一会话继续下一轮，旧运行和旧候选不变。

本地未保存记录/图谱草稿会阻止采用，请先保存或处理。其他页面/浏览器已保存的新版本也会在后端阻止旧候选覆盖。采用后新版本需要重新审核；旧审核仍绑定旧版本。重复点击采用只返回原回执，不再次建立版本。

## 已接通范围

- 骨架、细纲：新正文按纯文本段落安全写入HTML，旧版本保留；当前不会保留原富文本的全部格式，不是精确选段替换。
- 脚本：人物、场景、天气、时间、景别、机位、画面、台词、特效字和备注等文本更新；新增/删除见下方增量。已有话/格/批次身份、来源、引用和审核字段由后端保护。
- 生图包：场景、内容、站位、分镜、其他约束及完整提示词。人工完整覆盖模式下仅改分段不会静默改掉完整提示词，候选明确说明这一点。
- 画风/资产：提示文本、说明和备注。当前不读取图片像素，不重生成或替换参考图；不能把文字建议当作实图检查。
- 理解与记忆：实体名称、类型、摘要、别名、属性、重要性和关系说明等基本字段。修改写入改编层，保留原著层与证据，不修改图谱身份/资产绑定。图谱草稿和revision冲突保护仍生效。

模拟依赖在目标、附加资料和实际读取回执之间继承，不能经AI改写洗成正式来源；模拟依赖不能采用到正式图谱。记录`ai_run_id`与不可变版本、运行输入及工具回执相连。图谱历史注明采用AI候选，沿用人工确认字段的保护语义。

## 验证与剩余工作

`backend/agent_changes.py`负责候选校验与采用；`agent.py`装配API与受控工具；`AgentProposal.tsx`展示前后对照。测试见`backend/tests/test_agent_changes.py`、`frontend/src/AgentProposal.test.tsx`、Node工具桥测试。真实SDK→本机替身→候选→明确采用已实际跑通；真实供应商语义质量未验证。独立页面独立复审通过95/100，证据见`docs/pi-edits-ui-review.md`；仅覆盖本轮修改候选，不代表完整生产验收。

仍未完成：精确富文本选段改写、图片生产队列的真实生成替换、图谱状态与资产结构修改、图片像素读取/生成/编辑、视觉检查、旧五件套迁移、批次授权与恢复、系统自然语言配置助手。整个Pi集成目标保持实施中。

接口：运行摘要包含候选元数据；`GET /api/projects/{pid}/agent/proposals/{id}`按需读取完整对照，`POST .../{id}/adopt`采用，`POST .../{id}/reject`拒绝。`PUT /api/projects/{pid}/agent/sessions/{sid}/refs`以expected_version更新后续运行的绑定。修改工具一次最多100项、整包最多20万字符；普通文本字段有长度限制。运行未完整成功不能采用，版本或项目不匹配明确拒绝。

## 生产候选的文字编辑边界（2026-11-05追加）

采用AI文字修改仅更新正文版本。目标原本是正式主稿时，采用指针随新版本推进；目标是尚未采用、替换、待处理或已拒绝的生产候选时，不推进其采用指针，不清除候选标志，也不替代生产任务的明确采用关口。生产任务冻结输出版本仍生效：修改后的生成候选不能冒充原始任务输出直接采用，需重新生成并核对。旧任务的冻结输出和版本历史保留。

## 脚本新增与删除（2026-11-05增量）

在脚本助手明确附加当前已采用的脚本后，可要求AI新增或删除。`script_create`用该脚本作为话/批次锚点，指定1至10000内未用的整数格号及正文；允许空缺位置或末尾新格，不自动改动旧格号，也不复用历史格号（包括候选、已删除格及孤立下游包/图片）。无脚本的首次整话创建仍使用范围生成。新增候选不直接产生脚本，明确采用后建立待审核的新脚本。

`script_delete`仅允许附加脚本及非空删除原因。候选显示原画面和完整影响列表；明确采用后，以新版本撤下同格脚本、生图包、图片、通过script_id/package_id明确关联的下游内容和引用这些图片的试制确认，清除其采用指针，保留原文件、版本与审核历史。撤下记录的正文只读，不可经保存或图片历史采用重新启用；其他话格不重排、不删除。删除后可使用新格号重新创建。

话格、锚点或下游记录在冻结快照后变化（含新添依赖）会阻止整个候选采用，需更新资料重新核对。重复采用返回原回执；目标或下游存在本地未保存草稿时页面阻止采用。同一候选不能删除后再修改/引用同一目标，也不能重复占用新增格号。

脚本增删独立页面审核通过96/100，具体真实路径和边界见`docs/pi-script-crud-ui-review.md`。保留一般项：位置重复、新增差异标签冗余、已删附件缺少历史标识。最新追加的孤立格号及显式关联依赖由自动化验证，未计入该次页面服务证据。

## 独立生图方案与来源延续

画风/资产新讨论另有propose_image工具，只保存具体输入方案；不混入文字修改的采用事务，不自动调用图像模型。用户需先查看方案、创建预览，再确认1张；见[生图方案](agent-image-plans.md)。同会话历史mock已知依赖继续继承；在方案/文字候选提出后再读mock，也会更新当前运行候选来源，不能靠工具调用顺序洗白。新建独立讨论使用独立会话，但再次读取mock仍会保留。
