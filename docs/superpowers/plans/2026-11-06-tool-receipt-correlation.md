# 工具持久回执关联与只读对账实施计划

> 使用executing-plans，按原Pi阶段六授权增量实施。完整目标仍包含安全恢复；本段先补必要的持久证据，不以只读接口替代最终恢复。

目标：讨论及文本生产工具回执按项目/角色/运行/调用编号关联，宿主保存结果与业务事务一致，运行层登记精确输入及返回摘要；跨进程丢确认可只读区分“宿主已保存但Node未确认”和真正缺失，不能据缺失推断未执行。

设计：新增SQLite pi_tool_receipts。保留原agent_tool_calls/production_tool_calls及历史，不破坏回执列表；新回执和原业务写入同事务，重复调用复用原返回/不增加生产查询次数。Node每次tool_request增加输入SHA，Python沿用现有JSON序列化为result_json；Node校验result_json与data一致后登记SHA，不在检查点写工具正文。不同序列化的宿主语义输入摘要与Node摘要分别保存，不谎称跨语言独立算出同字节。旧无摘要记录不补造。

SDK分支：派发前保存当前会话leaf，只有当前assistant消息与SDK已持久entry可确认对应时才记录assistant叶；否则明确未核实，不按最新分支猜测。新增checkpoint_details仅返回登记元数据，不发模型/工具、不建目录、不写文件。公开对账返回摘要、存在性、匹配状态，不返回原著/结果正文、文件路径或密钥。
