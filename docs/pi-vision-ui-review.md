## 条件与实际页面

独立阅读PRODUCT.md、DESIGN.md、VisionReview.tsx/vision-review.css、Drawer及视觉API，应用已安装Impeccable产品界面原则。用Playwright CLI打开真实页面 http://127.0.0.1:5173，项目pi-review。后端18766、HTTP替身18767、假钥匙串和临时SQLite；全部写入仅为明确授权的隔离夹具。图片印有SIMULATION / NOT AI GENERATED。窗口1440×1000与1280×900。审查中后端两次经主开发备份保留数据重启，最终恢复定点在同步恢复修复版执行。

实际走通：

- 画风卡片→详情→模型视觉复查；检查目标和批准人物参考的版本/来源→预览→明确确认→报告、证据、区域矩形。预览HTTP读回status=prepared、raw=null；没有提前检查。视觉返回后画风和参考仍v1/approved，没有被复查修改版本或审核。
- 图片工作区→资料与问题→视觉入口。历史采用v1而head为v2时按钮禁用并有历史只读说明；切到当前v2可检查。选择脚本文字证据后预览，显示固定文字证据1项。
- 生图单图候选→生成本机替身图片→未采用结果的视觉入口，实际打开候选v1范围表单；候选仍adopted=0/pending/checked=false。该入口只检查可达性，没有再次执行同一报告全流程。
- 图片v1预览后API将head改v2，确认被409阻止。草稿localStorage夹具也阻止确认，清理夹具后可继续。修复后的错误提示在1280窗口内y=83px、高约47px，无需向上寻找。
- 慢速视觉替身：v2确认后立即停止，实际显示cancelled及“在途…完成及费用可能未知”，随后人工核对表单初始禁用；填写依据和确认后结束等待，显示人工结论。图片本身仍pending，未记录人工已检查。
- v3的无效视觉marker实际返回非JSON，UI显示“返回格式无效”，原始文字可展开，没有部分报告或自动通过。
- 仅在临时DB将该调用设received并提供已存合法raw，实际点击恢复。首审发现详情卡在旧received；最终修复版同任务再次设received，单击后立即出现“报告已保存”与无问题报告，不需手动刷新。此为构造已存返回的恢复页面验证，不是真实断网。
- 另在临时DB向已人工结束的任务补入raw，再真实HTTP recover并在UI历史查看，resolved与人工依据保留，报告可见；不是实际供应商取消后的迟到网络返回。
- 两段约2000字的合法长度问题/证据由临时DB构造，1280最终纵向占满内容行宽，严重度与图片编号不再逐字竖排。Esc最终只关闭内层视觉抽屉，保留资产详情且焦点回“模型视觉复查”。
