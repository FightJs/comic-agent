# 画风与资产模型生图候选

2026-11-05增量，完整Pi目标仍在实施。当前单图生成/目标重新生成已通过宿主图像服务调用OpenAI Images协议；实际供应商、型号账户权限、成本和语义质量尚未实测。自动三套同组代表画风、连续批量生图、图片区域返修、视觉复查和全局授权调度仍未完成。旧模拟按钮保持模拟标签。

## 用户操作

1. 配置图像用途的型号、服务基址和钥匙串密钥。保存配置不等于验证连接。
2. 画风或资产页点击“模型生图（单图候选）”，填写名称、完整提示词；也可从已保存的图片详情点击“用模型重新生成候选”，以当前记录版本为目标。
3. 资产必须已有确认且具有实际图片的当前画风，自动引用其固定版本。目标有图时作为第一张参考；附加参考仅可选当前已采用、审核通过的画风/资产。最多16张总参考，不把纯文本记录冒充图像。
4. 点击“预览模型与输入”，查看固定型号、数量1张、1024×1536、完整提示词、来源及实际参考版本。预览只登记，不向供应商发请求；修改要求需重新预览。
5. 明确“确认并生成1张”后才提交。调用次数上限1次，金额未知；不因超时自动重试。关闭抽屉不会撤销已授权请求，可重开查看本项目生图记录。
6. 返回图片仅为未采用候选，未视觉复查；主画风/资产列表不显示未采用候选。明确采用后才建立主稿或目标新版本，仍需审核；画风还要在详情明确确认。旧稿、文件与版本保留。

输入/目标存在未保存草稿时，预览、提交和采用会阻止。停止后续写入不受草稿阻止。讨论助手可先改提示文本，保存或采用文字后，再从该记录重新生成；助手不会绕过图像预览授权直接生图。

## 冻结与来源

- `backend/image_jobs.py`负责预览、显式启动、结果候选发布和人工核对；底层`image_provider.py`保持原请求幂等和返回持久化。`frontend/src/ImageGeneration.tsx`提供共用界面，`Preparation.tsx`接入两个阶段。
- 表`image_jobs`保存项目、预览token、调用id、固定输入、状态和输出归属。采用复用现有`/candidates/:id/adopt`，同时核对本项目成功图像任务、输出成员及冻结版本。
- 目标/参考版本、参考审核、资产的画风选择任一变化都会阻止未提交请求；已经出图时仍保存为候选，但过期输入不允许采用，不强制重新付费。切换到另一份未改版本的画风也会判定过期。
- 目标改稿不自动覆盖；重复启动同一任务不重复提交。已有同目标未决调用时，新预览或另一份预览启动被阻止。未决状态不能通过换token自动绕开。
- 模拟目标/参考继续继承mock。导入图被真实模型协议重新生成并采用后，新像素版本来源为ai；旧导入版本仍为import。仅修改导入图文字元数据不改变其像素来源。
- 候选采用后是新审核版本，不能继承旧审核。图片保存成功不等于视觉检查通过。

## 中断、取消与人工核对

- 预览可丢弃；排队/运行可“停止后续写入”。已提交的供应商请求不承诺撤销费用，返回继续保存，但不自动发布候选。若最终结果未知，仍进入待核对，不能因点击取消就视作无图。
- `received/interrupted`可“恢复原调用与登记”。有原返回时只恢复同一次返回，不重新请求；若重启前尚未提交，仍须核对原冻结输入，继续已授权调用。变化时阻止。
- `unknown`显示请求编号（供应商提供时）。先在供应商侧核对，再用表单记录“无图”或“系统外处理”及依据，并勾选确认；这只记录人工结论，不冒充供应商接口验证、不自动重试。已保存但无可用图的返回也可记录人工结论。
- 人工核对依据与勾选不跨任务复用。已核对后要再生图，仍须新预览并明确确认。
- 服务重启把排队/运行任务标中断；底层结果未知时归为unknown并保留人工核对入口。若已有原响应，也可从unknown只恢复原返回，不重新POST。不会自动恢复付费调用。全局预算、跨进程容量、自动重试及任务总览的统一调度仍待完成。

API：`GET/POST /api/projects/{pid}/image-jobs`（列表按kind筛选，POST仅预览）；`GET /:id`；`POST /:id/start|recover|cancel|resolve`。新任务不是旧模拟`/tasks`，不会将旧模拟重试悄然升级为付费请求。
