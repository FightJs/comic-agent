# 独立格图像批次

2026-11-05增量。已接现有宿主图像服务的独立格连续执行，后续固定前图依赖见`docs/image-dependencies.md`，可选检查/一轮剧情返修见`docs/image-postprocess.md`，暂停/有效预算见`docs/image-batch-control.md`；**不代表任意返修、全局文本/token/金额预算或真实供应商验收完成**。

## 操作

生图包页面常驻“批量图像任务”可重开历史，不依赖当前筛选或已选话格；勾选后可用“批量图像预览（N格）”。单批1–100格，沿用当前已采用包的完整提示词、话格身份、脚本/参考/图片槽位检查。未保存输入草稿先保存或处理。

1. 预览整批：不调用图像模型；每格显示固定包版本、实际提示词、型号、尺寸及参考。预览准备失败会保留可查的失败批次/已准备子任务，不授权剩余调用；从当前包建立新预览，不偷偷截断范围。
2. 核对全部固定输入并勾选授权，再点“确认并连续生成N格”。当前宿主图像容量1，无依赖时按所选顺序连续处理，有依赖时按固定图顺序处理，每格最多一次供应商请求；费用未知。普通顺序不自动当成前图依赖，声明`generation_dependencies`或`previous_image_dependencies`的包按`docs/image-dependencies.md`校验、冻结并等待前图采用审核；格式错误或缺少同批生成依赖包明确拒绝。没有声明的语义依赖仍需人工核对，本版不自动推断。
3. 生成返回仍是待采用候选。进入“查看单格任务”打开固定job_id，沿原单格页面核对图片、选择采用/拒绝或查询未知结果；不自动人工审核或采用；仅在所选策略明确允许时做一轮严重剧情返修。批次管理的子任务不能绕过原批次，从单格API或按钮独立启动/恢复。
4. 关闭面板不停止已授权批次。需要停止时点“停止本批后续派发”：阻止后续调用与在途候选写入，已提交费用可能未知、原返回仍保留。取消批次不直接恢复未提交部分；重新制作需新预览，未知原调用仍须先核对。
5. 暂停/中断/需核对批次可明确恢复：跳过已保存候选，继续未提交格或恢复已保存原返回。未知且无原返回不重发，其他独立格仍可继续。原调用成功但登记失败沿同一call_id恢复，不另扣一次生图。被阻止/拒绝/取消的子任务不会在恢复时擅自重试，详情保留原因。

“本批候选已保存”仅指全部单格任务成功保存候选，不代表最终采用、人工审核或视觉模型通过。部分未知、被阻止、拒绝或未出图时是“部分任务需核对”，不能冒充齐图完成。采用状态从各单格任务查看。

## 宿主边界和恢复

- 新`backend/image_batches.py`复用`image_jobs`的预览、queue/run、候选与provider账本；不复制第二套供应商调用、图片登记或采用逻辑。`image_batch_id`绑定子任务，外部单格start/recover不能绕开批次授权。
- 创建时先校验全部包、独立格身份与声明依赖，再准备单格预览；同批不能重复话格。同token输入不变返回原批次，换输入409。单格provider operation_id仍唯一，实际网络提交前再查当前输入/审核/采用/图片槽位与取消状态。
- 启动先检查全批尚未变化；执行到每格时再走原校验，等待中变更只阻止准确受影响项。其他无依赖格继续，最终保留部分失败状态。应用同时最多8个运行/排队或实际在途收尾的批次；并发付费调用仍受全局单图服务容量1限制。这不是完整全局token/金额/有效时长预算。
- SQLite新增`image_batches`，保存批次范围、子job_id、状态和错误；原输入/请求/响应/输出仍在原image_jobs/image_calls与不可变版本中。项目隔离、模拟来源继承、旧图不覆盖与原采用关口保留。
- 应用关闭先停止批次派发，再等待SDK关闭，避免退出等待期间新调用；重启将queued/running标中断，不派发；preparing标未完成。明确恢复沿旧输入、旧call_id和已保存输出，结果未知不重发。停止准备中的预览不会被迟到准备覆盖成可启动，停止时子任务恰好完成也不会导致后续子任务漏处理。

## API

- `POST /api/projects/{pid}/image-batches`：`{submission_id,packages:[{id,version}]}`，只预览。
- `GET /api/projects/{pid}/image-batches?start=0&limit=20`：摘要、total、next_start，每页最多50。
- `GET /api/projects/{pid}/image-batches/{id}`：批次及原单格任务详情。
- `POST .../{id}/start`、`recover`、`cancel`：明确启动、恢复和停止。
