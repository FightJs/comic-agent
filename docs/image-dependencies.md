# 固定前图依赖与实际像素绑定

2026-11-06实施增量。完整Pi目标仍在实施，当前代码和本轮验证以`docs/pi-progress.md`为准；本机替身不代表真实供应商画质、一致性、费用或权限验收。

## 用户操作

在生图包详情的“前图连续性依赖”中直接选择，无须手写JSON：

- **生成依赖包**：选择当前已采用的包版本；该包必须同时勾选进入同一图像批次。执行顺序由依赖图决定，不使用表格勾选顺序猜测依赖。
- **已有前图**：选择当前已采用且人工审核通过、有实际图像的图片版本。版本在预览时固定。

两类各最多8项，与批准资产参考合计最多16张；重复、循环、缺少所选父包、版本不符、跨项目引用均在创建子任务前拒绝。依赖只用于动作、空间和状态连续性，不能把前图升级为人物身份或画风权威。原“连续性说明”是文字备注，不自动添加参考或推断依赖。

保存生图包后，选择包含父包的批次并预览。提示词会附加宿主固定的连续性角色说明；未来图片尚不存在，页面明确显示“实际前图尚未绑定”，授权覆盖固定父格原调用返回在采用、审核后作为连续性参考。预览的基础图像清单不是已完整绑定的实际请求。

明确授权后，宿主按依赖顺序处理。父格生成仍是未采用候选，子格进入`waiting_dependency`，其他无关格继续。核对父格并采用，到图片工作区人工审核对应版本，再回原批次勾选确认并“明确恢复原批次”。只采用未审核、原生成未知/失败、拒绝候选、换成其他图都不会解锁子格。不会自动审核、采用或因等用户而偷偷生成。

当前单格按钮仍拒绝带依赖的包，要求从批次进入；不能用单格入口跳过计划。停止批次也停止等待中的格；重启不自动派发。付费调用结果未知时不重发，恢复跳过成功格，依赖解锁不会重新调用父格。

## 数据与调用

包内结构：

```json
{
  "generation_dependencies": [{"id":"package-record-id","version":2}],
  "previous_image_dependencies": [{"id":"image-record-id","version":3}]
}
```

字段缺失或空列表表示没有此类依赖。对象、布尔、仅话格号等旧式含糊声明拒绝，不静默清空。历史非结构化说明保留为文字，不能当成真实引用。

`backend/image_dependencies.py`负责严格声明、环检查、顺序及实际原返回解析；`image_batches`保留用户阅读顺序job_ids和单独execution_order。每个依赖job冻结`dependency_plan`，直接与传递祖先包版本纳入input_refs；生成后即使前图已采用审核，祖先包改动也会阻止尚未提交的后继格，须重新预览确认。预览时继承父格与参考的模拟来源。宿主检查实际父job成功及原call完成，只跟随明确`adopted_into`回执或同id首次采用，要求当前主图、采用、人工approved及原call_id/url/hash都匹配；不会“取最新图”或使用旧图替代。

未来前图解锁后以`dep:{job_id}`创建新的不可变图像调用，冻结实际参考id/version/file/hash和生产者job/call。原基础预览call_id记录在`preview_call_id`，原manifest不改写、原调用不派发。绑定前后检查原型号、参数、提示词、基础参考快照及批次/任务状态，再原子切换call指针；确定性operation_key保护准备后、切换前中断。最终提交还走原provider文件与引用检查、取消和全部输入检查。绑定时前图或已固定参考文件丢失/损坏只阻止该依赖分支，独立格仍继续；不是自动修复文件。

本轮依赖生成默认全部要求人工采用与审核；不提供“未审核自动流入下一格”选项。批次授权仍每格一次，不含视觉自动检查或修复；图像容量1，尚未实现完整全局预算和有效时钟。
