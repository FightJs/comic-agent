# 条漫 Agent

面向小说改编的本地条漫创作工作台：从原著整理、知识图谱、骨架与细纲，到逐格脚本、生图包、图像候选和人工审核，在同一个工作区管理资料与版本。

> **项目状态：首版，本机使用。** 基础编辑与数据持久化可用；文本、图像和视觉能力需要自行配置供应商。真实文本链路已做小样验证，真实生图曾返回 HTTP 429，视觉与长篇质量尚未充分实测。部分旧图片讨论流程为模拟，界面会标明来源。生成结果均需人工核对、采用和审核。

## 能做什么

- **原著与知识整理**：导入 TXT、Markdown、DOCX、PDF，保留原件与解析版本；配置文本模型后可整理卷章摘要和知识图谱，扫描 PDF 可选 MinerU。
- **前期策划**：编辑骨架、细纲、画风和资产；通过 AI 生成待采用候选，参考资料和版本可追溯。
- **逐格生产**：从细纲生成脚本候选，编辑逐格脚本与生图包；模型结果先核对再采用，不直接覆盖正式内容。
- **图像工作区**：预览并授权单图或批量生成，管理候选与历史；支持画布标注、批注定向编辑、视觉复查以及有限的自动返修流程。
- **审核与恢复**：区分模拟和真实来源、候选和正式版本；部分任务支持暂停、检查点续接和未知结果核对，避免自动重发不确定的请求。

完整操作和各阶段限制见 [使用手册](docs/user-guide.md)。

## 快速开始

### 环境要求

- macOS（启动脚本使用 zsh，API 密钥使用 macOS 钥匙串）。
- Python 3.11 或更高版本、Node.js 22.19 或更高版本及 npm。
- 首次安装依赖需要网络；使用 AI 功能还需要相应供应商账号、模型配置和额度。

### 安装与启动

```bash
git clone https://github.com/FightJs/comic-agent.git
cd comic-agent
./start.command
```

也可在 Finder 双击 `start.command`。首次启动会创建 Python 虚拟环境、安装锁定依赖并构建前端。脚本优先使用 PATH 中符合要求的 Node，也会查找本机 nvm 安装的合格版本。

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。在启动终端按 `Ctrl+C` 停止服务。服务只监听本机，不提供公网访问或账号协作。

### 首次使用

1. 新建项目，导入原著；根据解析结果检查章节和原文。
2. 在“模型设置”中配置文本、图像或视觉供应商。密钥保存在 macOS 钥匙串；保存配置不代表连接或模型效果已验证。
3. 整理知识图谱、骨架、细纲和资产，再生成并审核逐格脚本与生图包。
4. 在预览中核对输入、模型与调用数量，明确授权生成；逐项检查候选、采用并人工审核。

AI 请求可能产生供应商费用，实际能力、额度和价格由所选供应商决定。配置包格式见 [配置说明](docs/config-packages.md)，分步骤操作见 [使用手册](docs/user-guide.md)。

## 功能边界

| 能力 | 当前情况 |
| --- | --- |
| 本地项目、编辑、导入、版本和审核 | 已实现；数据保存在本机 |
| 小说图谱与记忆 | 已接可配置文本供应商；真实长篇抽取的成本、耗时和语义质量尚未充分实测，摘要不能代替原文 |
| 骨架、细纲、脚本和生图包 | 已接 Pi 文本调用与候选采用；真实供应商的生产质量仍需验证 |
| 图像生成、批次、视觉复查和批注编辑 | 已有预览授权与候选流程；真实生图小样曾返回 429，视觉效果尚未实测 |
| 图片工作区旧批注讨论及旧按方案生成 | 模拟流程；正式批注编辑使用“按批注编辑图片”入口 |
| 长条排版、绘画编辑器、账号协作、XLSX 模板及文档导出 | 尚未实现 |

首版验证记录见 [首版交付说明](docs/v1-release.md)；更详细的实现、历史验证和未完成事项见 [开发交接摘要](docs/开发交接摘要.md)。模拟图片仅用于演示流程，不代表模型生成效果。

## 数据与备份

项目数据库、导入原件、生成图片和运行记录保存在项目目录下的 `data/`，该目录已加入 Git 忽略规则。API 密钥保存在 macOS 钥匙串，不随仓库或 `data/` 备份迁移。

**`data/` 不是缓存。** 备份前请停止服务，然后复制整个目录；恢复及未知请求处理步骤见 [备份与恢复](docs/backup-restore.md)。请勿将原著、生成素材、数据库或密钥提交到公开仓库。

## 开发

启动一次 `./start.command` 安装依赖后，可分别运行后端与前端开发服务器：

```bash
.venv/bin/python -m uvicorn backend.app:create_app --factory --host 127.0.0.1 --port 8765
npm run dev --prefix frontend
```

前端开发地址以 Vite 输出为准，API 请求代理到本地后端。修改前端后用于本机正式启动的构建可通过 `npm run build --prefix frontend` 更新。

```bash
.venv/bin/python -m pytest -q
npm test --prefix frontend
npm run build --prefix frontend
npm test --prefix agent-runtime
```

历史验收结果及其适用范围见相关专题文档；上述命令是本地验证入口，不代表每次发布均已重新运行全量测试。

## 项目结构

```text
backend/        FastAPI 服务、SQLite 存储、生产流程与测试
frontend/       React / TypeScript 工作台
agent-runtime/  Pi 模型运行时及测试
resources/      内置流程与规则资料
scripts/        辅助脚本
docs/           操作说明、实施与验证记录
```

技术栈包括 React、TypeScript、Vite、Tiptap、Konva、FastAPI、SQLite 和 Pi SDK。前端、Python 和运行时依赖分别由各自锁文件固定。
