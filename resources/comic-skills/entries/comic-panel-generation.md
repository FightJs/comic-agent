# 条漫逐格输入与生成（工作台移植）

适用于已采用脚本/视觉基准/逐格包的提示词编译、优化、单图生成方案与必要返修建议。先读[工作台合同](references/workbench.md)。不自行启动旧宿主进程或把脚本示例当已注册工具。

1. 保留本次批准源格号、版本、动作结果、人物身份、衣装、场景和画风。接续任务复用已采用实际包，只对真实变化做范围修订；不因缺个人配置重新设计整话或寻找外部工作目录。
2. 生图包按宿主schema分别写场景、内容、站位、镜头与约束等已有字段。实际绘图提示词必须明确唯一机位、画幅、裁切、人物可见动作、作用对象、衣装/关键细节和必要背景；不能把预算、审核签名或分析长文当作绘图指令。
3. 实际参考逐一说明角色、当前版本与用途；同图去重、预算不超过五份且服从宿主更严限制，不静默丢关键证据。全身/全景参考不扩大本图取景，失败图不能升为身份/画风依据。
4. 核对全文无相反旧模板、双格指令或重复肢体目标。单图预览冻结真实提示词、参考和型号后由用户明确启动；模型文字候选不等于付费调用授权。宿主未提供自然语言图像计划工具或批次执行时，只返回准确方案与可用入口。
5. 返回原件、真实请求/响应与attempt沿宿主存储，不覆盖旧图。未知不重发；恢复只用同一次原返回，不能把重新调用冒充恢复。视觉报告独立排队，不写人工审核通过。
6. 基于实际问题提出留人工、一次合并局部修复或重生建议。严重剧情问题至多一轮必要自动返修的原政策仍须宿主实现及明确授权，当前不能以规则包冒充自动编排。局部修复说明真实底图、错误删除、新结构连接与保护范围；整体空间/机位错误先修输入，不能拆框掩盖。
7. 保留原失败、有效修正与预算，内容拒绝不自动重试。只有宿主明确证明无图且提供受控重试策略时才走技术恢复；不把异常、超时或迟到返回当作无图证明，不在模型里自行循环四次请求。
