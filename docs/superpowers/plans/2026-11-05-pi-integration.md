## 二、架构与当前代码入口

采用 React → FastAPI → Pi Node 子进程。浏览器只访问 FastAPI，Python 独占业务数据库写入，Node 不直接修改业务表。

| 层 | 职责 |
|---|---|
| React | 讨论、方案确认、启动、进度、中止、审核与采用 |
| FastAPI / SQLite | 数据、版本、授权、调度、回执、文件与恢复 |
| Pi 完整会话 SDK | 会话持久化、上下文压缩、skill 加载、工具循环 |
| 项目工具与适配器 | 证据查询、批准资产读取、生成提交、图片保存和检查登记 |

新增独立 `agent-runtime/` Node 包，由 FastAPI 生命周期管理，通过双向 JSONL 标准输入输出通信。不自行重写 Pi 执行循环，初期不修改 Pi 上游。

当前入口：

- `backend/app.py`：装配、基础任务、模型配置、钥匙串与关口；`backend/workflow.py`：讨论、生产任务、候选采用。
- `backend/store.py`：版本、原件与事务；`backend/graph_engine.py`：图谱调度及当前直接模型调用。
- `frontend/src/Workflow.tsx`：讨论、方案和任务；`Production.tsx`、`Images.tsx`、`Preparation.tsx`、`Auxiliary.tsx`：相关页面。
- `start.command`：一键启动；现有数据目录 `data/`，数据库 `data/workbench.sqlite`。
- 本机原始条漫 skill 位于 `/Users/xiaochao/.codex/skills/vertical-comic-*`。此路径仅供迁移时读取，交付运行不能依赖个人目录。

现状：基础编辑、导入、审核、标注和下载已实现；图谱有真实供应商调用代码，但现有验收主要用替身。其他创作生产环节仍有模拟执行器。讨论、生成已保存版本引用和输入快照，应复用。

## 三、分阶段任务与验收

### 阶段一：运行底座和工具桥

- [ ] 建立独立 Node 包与锁文件。要求 Node ≥22.19，先检查 SDK 实际导出和示例，再锁定稳定版本；不要仅依赖可变的 latest 文档。
- [ ] 显式配置模型、凭据、工具、会话及资源加载器，隔离全局 Pi 配置、个人 skills 与开发 AGENTS.md。
- [ ] 默认不开放 Bash、任意文件写入或代码修改工具；配套脚本通过登记的业务工具执行。
- [ ] 实现协议版本检查、健康检查、执行、取消、关闭、工具请求/返回、事件和最终结果，以 request_id/run_id/session_id 关联。stdout 只输出协议。
- [ ] Python 监督退出、清理在途状态，运行层失败不能阻断基础编辑与人工审核。启动和关闭均管理子进程。
- [ ] 文本密钥从钥匙串经管道注入 Node 内存，不能进入日志、命令行参数、会话或 SQLite；图像密钥留在 Python。
- [ ] 一键启动安装独立包依赖并校验运行版本。

验收：空配置、缺依赖、协议不兼容、启动失败、中途退出和正常关闭均有明确状态；工具不能跨项目访问。

### 阶段二：会话、上下文与记忆

- [ ] 将业务讨论映射为持久 Pi 会话，同一会话串行执行；新消息在当前回复结束后提交。
- [ ] 讨论仅有读取和方案权限，点击生成后才建立具有写入及付费调用权限的运行。
- [ ] 复用 conversation_id、refs 和 version；生成时冻结方案、对话版本及输入引用。
- [ ] 开启 Pi 自动压缩，每次任务重新注入任务目标、不可变引用和授权范围，不依赖摘要保存业务约束。
- [ ] 对话历史由 Pi 管理，正式人物/剧情/资产由现有版本数据管理；跨会话偏好使用项目级可编辑、可删除记录，用户明确保存后生效。
- [ ] 会话文件存入项目数据目录并纳入备份；保存会话映射和运行检查点。
- [ ] 历史模拟对话只作明确标注的参考，不直接变成正式模型历史，模拟来源继续保留。

验收：多轮修改、刷新、重启、压缩后继续、项目隔离及版本绑定正确；讨论不产生图片任务。

### 阶段三：条漫 Skills 和业务工具

- [ ] 迁移五件套：前期协调、视觉资产、镜头设计、逐格生成、图片审核。建立逐项迁移清单，保留创作规则与资料，替换专属工具名、绝对路径、外部启动及重复账本。
- [ ] 支持相对与跨 skill 引用，检查完整性；先目录后按需读取正文和资料。已知业务阶段由宿主明确加载必需 skill。
- [ ] 冻结运行的 skill 包版本与内容哈希；更新只影响新运行，恢复沿用旧版。
- [ ] 提供工具：原著证据查询、版本读取、批准资产查询、候选提交、生成请求、实际图片读取、检查与问题登记。
- [ ] 前期、编排、渲染、视觉审核分离上下文和工具权限；审核读取实际图片、原著和批准参考。
- [ ] 唯一性、额度、版本和审核关口由后端强制执行，不能被 skill 文本或模型自述覆盖。

### 阶段四：真实文本流程和图谱入口

- [ ] 逐个替换骨架、细纲、逐格脚本、选格修改、生图包的模拟执行器，保持现有入口、快照和候选比较。
- [ ] 为各产物建立结构校验；普通回复不直接写成业务结果。新话按真实输出建格，不再固定三格；修改仅作用于选中格。
- [ ] 统一供应商配置、流式输出、用量和错误，支持官方及已验证的兼容文本接口。
- [ ] 图谱经同一 Node 模型适配模块受约束单次调用，不加载创作记忆、不开放工具循环，保持原发布语义。
- [ ] 格式错误最多一次结构修正；仍失败保存原始返回和错误，不静默写入无效部分。
- [ ] 正式候选默认未采用；输入过期另存待处理候选，不覆盖当前版本；模拟依赖不能变正式来源。

注意：当前 Store.add 默认 adopted=1，新增正式候选要显式处理未采用状态，同时兼容现有查询与首次候选的采用入口。

验收：一话真实细纲→脚本→生图包；覆盖并发、迟到回复、结构错误、版本冲突和图谱回归。

### 阶段五：图像生成、检查与返修

- [ ] Python 实现 OpenAI Images 生成与编辑适配器。型号明确配置，按官方文档与账户实测启用，不自动换型号。
- [ ] 分别验证无参考、多参考、底图编辑和蒙版能力；不支持的参数明确禁用。
- [ ] 调用前登记完整提示词、实际参考版本和参数、输入摘要及 attempt；返回后先保存原始响应和图片，再登记业务版本。
- [ ] 工具使用幂等操作标识；重复请求返回原调用或结果，不重复扣费。
- [ ] 超时、断线且执行结果未知进入待核对状态；无法查询时停在人工入口，不自动重发。
- [ ] 视觉角色读取实图与批准参考，输出结构化问题和证据，保存成功不代表检查通过。
- [ ] 修图绑定底图与批注版本、区域和保留要求；坐标文字不能当成硬蒙版。
- [ ] 严重剧情问题最多一轮自动返修；明确确认无图的网络失败最多重试四次；内容拒绝不自动重试。普通瑕疵记录后交人工。
- [ ] 图像和视觉独立容量，图像持久化后释放生成槽。

验收：真实代表格生成、实图检查和一次返修；保存/登记失败恢复同一返回，不再次生图。

### 阶段六：授权批次、并行与恢复

- [ ] Python 按批准输入→编排→生图包→生成→检查→必要返修→待采用调度固定角色。
- [ ] 每格记录状态、attempt、输出和问题；真实前图依赖只阻塞相关格，其他就绪格继续。
- [ ] 授权绑定版本、范围、操作、并发和调用上限；输入改变使受影响未提交工作等待重新确认。
- [ ] 初始并发：文本2、图像1、视觉1，可配置且服从供应商限制。
- [ ] 单次 Pi 运行最多20个模型轮次、50次工具调用，达到后保存检查点并暂停；不能自动另开运行绕过额度。
- [ ] 批次四小时目标、七小时有效运行硬限，等用户不计有效时间。
- [ ] 暂停停止新派发；取消阻止后续动作，已提交请求仍核对并保存返回。
- [ ] 重启先处理未决调用和已返回未登记文件，再恢复未执行工作；分别判定会话恢复和工具恢复。
- [ ] 汇总真实用量、可观测耗时；未返回的数据标未知。

验收：乱序返回、局部失败、重启和取消可恢复，每次付费调用有唯一记录。
