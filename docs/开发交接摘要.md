# 后续开发交接摘要

实现依据：根目录《系统界面与基础功能交接方案.md》。默认在当前工作台增量开发，不替换已确认的两条业务流程。

后续接入真实AI时保留：来源继承、项目隔离、不可变版本、输入冻结、审核版本与关口、历史底图和标注坐标、独立采用决策。真实供应商代码接在服务层，不散落页面组件。候选模型名称仍须查官方接口，不能把模拟标识移除后当作联调完成。

modules[6]{area,path,responsibility}:
  persistence,backend/store.py,SQLite事务与不可变版本及原件文件
  api,backend/app.py,项目接口及关口审核导入任务与钥匙串
  simulation,backend/simulation.py,明确标注的确定性样例且无网络调用
  workspace,frontend/src/App.tsx,项目和两套流程及上下文定位
  editing,frontend/src/useDraft.ts,自动保存冲突与未保存草稿恢复
  canvas,frontend/src/AnnotationCanvas.tsx,原图坐标标注及保护区独立保存

命令：`./start.command`；后端 `python -m pytest -q`（项目 .venv）；前端 `npm test --prefix frontend`；构建 `npm run build --prefix frontend`。

TOON 用于上方统一字段的模块表；业务约束保留直白文字，不把不规则配置强行表格化。当前安装的 toon skill 缺少 references 目录，故仅采用其主文件给出的保守压缩规则，不声称运行了缺失的转换脚本或取得了实测 token 节省。

## 批次制作重设计增量

- 新生产API位于 `backend/workflow.py`：细纲话索引、讨论会话、批量任务、候选采用；`app.py`装配路由并将重试分流至生产worker。
- 前端 `Workflow.tsx`：生成范围、讨论/方案、同组结果；`Production.tsx`：完整脚本审核与分段生图包；`Images.tsx`：统一图片工作区。
- 模型接入时必须沿用冻结输入和显式生成边界。讨论消息不产生图片任务；只修改选中话格，格号和身份不变；结果候选不自动采用。
- 修图提交携带 `annotation_versions`，版本变化返回409；首次生成同话格任务需串行占位，防并发重复主稿。
- 原有自由文本细纲保留，以版本化 `outline_index` 建立话级映射；已有旧生图包不自动猜测拆分提示词。
