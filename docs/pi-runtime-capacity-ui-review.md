## 实际走通的路径与状态

1. 项目库 → 模型设置，1280×900默认2/1/1，运行/排队0；滚动检查完整容量三行、说明及保存区。证据 `1280-default.png`。
2. 文本上限通过键盘End选8，Esc关闭菜单保持抽屉，Esc关闭抽屉，再打开仍保留草稿8；保存成功后整页刷新重开可读取已保存值。三类Select后续均通过Home/ArrowDown遍历1–8并保存8，文本又保存1；没有逐一提交全部24种组合。
3. 1440×1000，文本本地1，隔离API将服务端更新3/2/2，刷新显示最新已保存值、保留本地1，禁用保存。点“已核对最新设置，保留我的输入”后再明确保存成功。证据 `1440-conflict.png`。
4. PUT 503夹具：输入8、保存报“隔离审核：保存暂时失败”，保留8和旧已保存值，移除路由后点击保存成功。证据 `1440-put-error.png`。
5. GET 503夹具：关闭重开时无快照，显示读取失败和刷新恢复提示，无可提交表单。移除路由，点击刷新恢复。证据 `get-error.png`。
6. 4个隔离setup慢速请求，文本容量2，真实UI刷新显示“运行2 · 排队2”，图像/视觉0。证据 `active-waiting.png`。这是真实本机Pi调用路径上的替身请求，不是真实供应商效果验证。
7. `pi-review` → 模型设置，共享容量和项目库相同，三类表单一致。证据 `project-capacity.png`。
8. 文本容量8时创建3个隔离慢速请求，再通过UI缩到1，保存后显示“运行3 · 排队0；当前已保存1”，说明“不终止已提交请求”在下方可见；收尾后刷新回0。证据 `shrink-active.png`、`settled.png`。
9. 最新dist：`pi-review` → 批次制作 → 逐格生图包 → 选第1话第1格 → 批量预览。初次因图像配置缺失被真实页面阻止；随后经隔离API配置 image 为18767本机替身、ui-fixture/openai-images，重新实际UI预览成功。未勾选时确认禁用，勾选启用，取消再次禁用；勾选后切回“查看所选包的新预览”并重新预览，授权框重置未勾选、确认禁用。未点击生成按钮。证据 `batch-reset.png`。并发说明已改为受共享容量约束。
