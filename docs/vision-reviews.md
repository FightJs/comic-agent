# 实图视觉复查底座

2026-11-05。完整Pi目标仍实施中。单图视觉检查已有宿主服务、Pi实际图片输入、显式预览授权及报告页面；操作和HTTP入口见下方“页面与显式授权增量”。自动批次、原著证据/视觉Skill与有限返修仍未完成，真实供应商效果未验证。

## 当前能力

- `app.state.vision_reviews`在`backend/vision_reviews.py`注册。内部`prepare`冻结目标、批准参考、当前已采用脚本/包文字证据及视觉型号；`execute`明确执行受限Pi单次调用。图片与视觉使用独立容量槽，各为1；服务不自动生图或返修。
- 从本项目文件读取真实PNG/JPEG/WEBP字节，核对文件归属、hash、当前版本、采用指针与参考审核。最多8张（含目标），每张4MiB、总计6MiB；超限拒绝，不截断或暗中降采样。顺序1是目标，其后为批准参考。参考不得重复目标或彼此重复；当前目标可为尚未采用的候选。
- `agent-runtime/src/server.mjs`的`complete`支持原生Pi图片内容，模型仅在有图片的受限调用中声明图像输入。校验base64/MIME/签名和总量，只接受字节，不接受外部图片URL；不启用工具、创作会话、个人资源或磁盘会话保存。JSONL请求上限9,000,000字符，原文本长度限制保留；Python返回读取上限未扩大。
- 配置与凭据在同一配置锁内读取，准备阶段只读公开配置、不读取密钥；实际提交前再次检查配置及固定资料。密钥经管道进入内存，原始图片base64不写视觉账本或Pi会话。
- 固定文字包含图片提示词/描述及调用者明确提供的脚本/包版本；不自动假设原著正文已被读过。当前尚无原著证据范围选择及视觉专用Skill加载，prompt明确禁止据此声称符合全书。

## 结果与恢复

SQLite表`vision_reviews`保存操作标识、输入清单、状态、原始文字返回、结构化报告、实际可用用量与错误；金额未知。每项目operation_key相同输入幂等，异输入冲突。无隐式重试，未知请求不重新提交。

返回先保存为received，再校验summary/issues。这里只校验报告结构及引用范围，不证明模型观察或语义判断正确。问题需要明确严重度、类别、可观察证据、有效图片编号；可选region为目标图归一化矩形，越界/无效坐标拒绝。格式或证据引用无效保留原返回，状态invalid，不发布部分报告。恢复已保存返回只重新校验，不调用模型。

完成报告与当前输入过期状态分开。即使无问题，报告也不修改图片checked、review或业务版本，不替代人工审核，不自动放行生产。取消排队不提交；取消在途向相同run_id发送取消，已到文字返回仍保存且保持cancelled。供应商取消后未返回的费用/用量未知。应用重启将running标unknown；received可仅恢复原返回。

报告中对照实际目标及参考版本，问题显示严重度/类别/观察依据/图片编号，区域按钮在图1叠加模型估计矩形。矩形不是硬蒙版，也不改变标注。原返回、无效格式、输入过期和未知费用单独显示；报告不自动写checked、不生成审核记录。已采用主图与未采用候选都可检查，历史图片只读，请切最新版本发起新检查。

每个检查独立预览/授权。相同图片queued/running/unknown或无返回的在途取消未核对时，不能用新预览绕过未决调用。未知先在供应商侧核对，填写依据并明确结束等待；仅保存人工记录，不声称验证供应商费用或完成情况。再检查仍须新预览和确认。人工结论后迟到返回仍保存，保留resolved及依据，不覆盖人工决定。

关闭不撤销已提交检查，可重开查看。服务重启将queued标interrupted（未提交，恢复需再次确认原授权），running标unknown（不重发）；received或已存文字原返回可只恢复校验。排队实际派发前仍核对版本/文件hash/审核/配置，变化时blocked且未调用。

API：`GET /api/projects/{pid}/vision-reviews?target_id=...`是精简历史；`POST`只预览；`GET /:id`详情；`POST /:id/start|recover|cancel|resolve`。resolve要求confirmed=true与非空核对依据。未知不能直接recover重发；有原返回的recover只校验。所有接口绑定项目，支持幂等操作标识，未知用量null。

## 原著证据与审核Skill增量（2026-11-05）

当前单图检查可在“添加原著证据”选择小说、按章定位或设置字符起止范围，先读取并明确加入检查；移除的片段不会提交。每次最多10段，每段10000字符、合计30000字符。前端只发送文档id/解析版本/位置，后端从本项目原著读取精确引文；不接受客户端自行提交quote。字符位置为Unicode码点，终点不含；读原文期间改范围，迟到返回不会恢复旧选择。

预览保存精确quote、文档/解析版本、字符位置、解析覆盖警告和原著记录来源。显式旧解析片段可作为历史依据，预览会说明其与当前解析不同；预览之后再有新解析或原著版本变更，未提交检查被拦截。历史报告仍保留旧引文，不静默切为新版。缺页/OCR警告不等于全书不存在，也不能把一段原文当作全文理解完成。

项目已启用且适用于review阶段的Skill自动在预览冻结hash/版本/主规则及Markdown相对引用资源闭包；循环只读一次，不加载未引用资料、不访问外部URL，不执行任何脚本。规则与引用合计最多80000字符/1500资源，超限拒绝，不截断后冒充完整规则；全部视觉文字清单另受180000字符总限。规则仅补充检查重点，不改变宿主权限、结构校验或人工审核关口。变更项目流程只影响新预览，已授权运行及恢复继续使用原固定规则。

视觉问题可带source_evidence：每项指定原文序号、绝对start/end和精确quote。后端逐项核对所选范围及实际字符串，伪造/越界引用使整份结构化报告无效，保留原返回，不自动重试。这只证明引文/位置匹配，不证明模型的图像观察、推理或改编判断正确；未引原著的问题仍仅按图像/脚本证据理解，不能声称核对全书。

`POST /vision-reviews`新增可选`source_ranges:[{document_id,parse_version,start,end}]`。旧无原著/无审核Skill的记录继续按旧固定输入显示和恢复。当前仍未迁移原五件套、实现自动有限返修或真实供应商语义联调。

实现：`backend/vision_grounding.py`、`frontend/src/VisionSources.tsx`及视觉服务/页面。新增回归`backend/tests/test_vision_grounding.py`和`VisionReview.test.tsx`。页面隔离夹具加`PI_REVIEW_VISION_GROUNDING=1`可启用演示审核规则并让替身返回精确所选引文；不是小说理解或实图语义质量验收。独立增量审核记录`docs/pi-vision-grounding-ui-review.md`，最终数量见执行记录。
