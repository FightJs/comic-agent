# 同组三套画风测试方案实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. 当前用户已授权完整Pi计划及连续迭代，无须重新请求是否开始；本计划是原阶段三/五/七的具体化。

**Goal:** Pi基于固定原著证据与已审核细纲，提出同一主角/主场景的三套二维画风测试；每套独立预览、明确生图，候选并排核对并保留来源与输入守卫。

**Architecture:** 新增受控propose_style_tests工具，在同一事务产生一个不可变测试组和三份现有agent_image_plans。每套一张含身份/多视角/表情/剧情场景的试验板，复用image_jobs和ImageGeneration，不新增供应商或绕开采用/审核。当前增量分别授权三张，后续整组连续派发仍按原完整计划补齐，不宣称自动批次已完成。

**Tech Stack:** React/TypeScript、FastAPI/SQLite、锁定Pi SDK；不加依赖。

**Spec:** 原系统范围与开发进度基线3.3、2026-11-05-pi-integration.md、PRODUCT.md。

## 设计裁定与约束

- 三张完整试验板优于六张独立人物/场景图：符合基线“组织为几张属于实现细节”，每套内部可直接比较人物与场景表现；仍需实际生成效果和人工核对，提示词不证明身份或画风正确。人物多视图/表情是测试板排版，不把正文单画面规则误用到资产板。
- 3个方向固定A/B/C，完整共有主角/外观/主场景/环境/动作相同；差异只由线条、比例、上色、阴影表达。服务端统一编译提示词，不让每套自行更换共有输入。
- 至少一段宿主读取的固定原著范围及一份固定、已采用审核的细纲；人物/场景名称须出现在原文引用中。语义及合理补充仍人工审核，不伪称全书通读。
- 不接受APIkey、型号、URL、脚本、额外工具或图片目标；旧tools=true/旧显式白名单不新增权限。新工具仅新style运行开放，原检查点权限不热改。
- 资料版本/审核/采用、原著解析/选择、图谱、偏好、已启用Skill变化在预览、等待出队、候选登记/采用时复核；返回可保存，过期不洗白。已知模拟历史/引用/迟读继续继承。
- 不自动生图、采用、审核或确认画风。预览每套1次，未知请求仍不重发，沿原单图恢复入口。完整自动三套批次及真实供应商质量仍原goal待办，不缩小最终目标。
- 工作树原有修改保留，不reset/clean/从HEAD重建，不自动提交混合工作。
