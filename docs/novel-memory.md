# 固定版本的卷章摘要记忆

在“理解与记忆”等页面顶栏打开AI助手，可要求“查阅当前原著的卷章笔记，并用原文核对依据”。原著整理任务完整发布后，助手可以读取其卷、章摘要；工具不会自行启动额外抽取或付费任务。整理未完成时仍可查询已有解析原文，但不会把零散笔记当作全书记忆。

默认使用当前成图原著；没有选定来源时使用最新导入。明确附加一份原著时，以该固定版本为准；同时附加多份原著时须明确文档，不擅自挑选。新消息/新任务冻结新的摘要绑定，既有运行不随后台新任务完成而改变。解析更新后，如要使用新版本，可“更新附加资料到已保存最新版本”；若换成另一份导入，则新建讨论选择该资料。

## 数据与权限

- `freeze_context`记录每份固定文档解析版本对应的最新已发布原著任务。只选择`kind=document/status=succeeded/stage=published`，且所需摘要单元完成；排除失败、取消、运行中、被取代和OCR不完整的版本。
- `backend/novel_memory.py`复用`graph_jobs/graph_units`已有数据，无新抽取、无原著改写、不新建业务产物。每次读取检查项目、文档、解析版本、任务和单元归属，不能用任意任务id越权取数据。
- 本次默认原著与绑定写入运行/生产快照；Agent运行API返回`preferred_document`和`novel_memory`，工具回执保留实际读取的摘要。旧运行缺少绑定时返回`not_frozen`，不会悄悄选择后来完成的任务。
- 讨论和文本生产角色都可查询；文档生产仍限定当前原著，未选原著不能从摘要工具绕过输入范围。模拟原著的摘要继续标记`mock`，不能用笔记洗掉来源。

## 受控查询

使用既有`project_query`，新增`action=novel_summary`。`id`是文档编号；省略时只使用本次明确默认原著。`start/limit`用于列表分页，每页至多20单元。

| query | 含义 |
|---|---|
| 空或`volume` | 卷摘要单元列表 |
| `chapter` | 章摘要单元列表 |
| `chapter:解析章节序号` | 按解析index定位该章所有摘要单元，不是猜测标题中的数字 |
| `volume:完整卷名` | 定位该卷的摘要单元 |
| `search:关键词` | 在模型摘要内做字面检索，不等于原文检索 |
| `unit:单元编号` | 按start读取该单元的摘要正文，每次至多一万字符 |

列表正文每单元最多4000字符，附`truncated/next_text_start/total_chars`；继续读取用unit查询。列表附total与next_start，包含中间页，不只截首尾。同一章/卷可能有多个单元，应按unit_id区分；不可合并掉后续部分。长标题会明确标记截断。

状态分为ready、not_ready、not_frozen、unavailable。未就绪包含已知任务进度；固定任务不可用时不会改读别的任务。catalog同时列出可用摘要与解析coverage，便于选择资料。

## 原文与笔记分开

`source=model_summary`表示模型整理笔记，不能当作原文引文或当前改编层事实。chapter locator只给章范围，不是该摘要的精确引文位置；精确引用继续使用source/search_novel的文档、解析版本和Unicode位置。摘要无命中也不能证明原著没有该事实。

提示词要求先查看需要的卷章笔记，再核对原文，不能声称读完未查分页。**摘要可用不等于模型已读完、理解正确或真实长篇质量通过。** 当前仍有每次工具/轮数额度；全书覆盖审计、SDK压缩保真与记账、真实长篇成本/时长/语义验收尚未完成。
