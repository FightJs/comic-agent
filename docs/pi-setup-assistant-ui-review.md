## 问题（按严重程度）

阻断：无。重要：无。

### G1 一般：长名称使移除按钮过高

位置：AI配置与流程助手→附加包列表。复现：上传120字符Skill名称（含114个连续A）的合法包。现象：右侧按钮显示“移除”及完整名称，换为约九行，高度约200px；左侧规则因此剩余宽度较小。影响：增加视觉重量和滚动成本，但没有遮挡或横向溢出，关键操作可完成。建议：按钮可视文字统一为“移除”，完整名称保留在可访问名称或说明中。证据：`/tmp/pi-setup-long-1280.png`、748/748及541/541宽度读数。

### G2 一般：应用在途关闭后，附件标签滞后

位置：助手附加包与同一会话历史。复现：对隔离配置候选点应用，构造apply响应在后端完成后延迟1.5秒返回；响应到达前Esc关闭，返回后重开。现象：历史准确显示“已应用·连接未验证”，附件仍显示“配置包·尚未应用”。本次重复构造后DOM同时有1份上述附件和对应成功历史；并未因此重复执行配置。影响：用户可能误以为还需处理该附件；实际配置与候选成功状态正确，历史采用控件已消失。建议：成功响应即更新持久的内存附件映射，再判断组件是否仍挂载，或重开按历史成功操作同步附件状态。证据：上述stale-attachment与stale-history两图及本条件复现。暂留后续完善。

## 实际操作与修复复查

- 手动模型草稿填入`unsaved-ui-model`：AI入口、直接导包和用途切换禁用，草稿保留；还原后恢复入口。
- 配置包：核对前应用禁用；核对后应用成功，显示连接未验证。稳定重复后正常移除已采用附件。
- Skill：上传不自动安装；未安装先启用被阻止；独立安装后显示未自动启用，再保存本项目流程成功。只读API核对项目revision1与已安装hash一致。
- Skill草稿：取消已启用项但不保存→打开助手采用项目选择被阻止，提示先保存或放弃；关闭后通过“放弃草稿，读取最新选择”恢复。
- 空/错：无会话提示、无效模型返回、4秒慢请求主动取消、供应商500中断均实际查看；取消后迟到结果没有变成候选。构造发送端点503后输入保留，关闭重开仍保留。
- 配置冲突：真实隔离API对同值设置PUT以推进revision，再采用旧候选，得到409“配置在预览后发生变化，请重新导入并核对”；拒绝旧项后重新上传、讨论、采用恢复成功。拒绝项不再有采用控件。
- 首次配置：仅在浏览器GET响应构造无文本模型/密钥，入口清晰；取消拦截后上传loopback文本配置包，采用后首次配置块消失，原草稿保留。此项没有实际清空后端配置。
- 直接导包忙态：浏览器route延迟12秒，处理中模型输入disabled=true、AI入口disabled=true，有明确处理中说明；结束后恢复，不覆盖手工草稿。
- 已修复的关闭竞态：构造创建会话POST延迟1.2秒，发送即关闭、响应后再开，草稿仍在新sid；构造现有会话messages响应延迟1.8秒，关闭后重开移除附加包，再核对采用仍成功，未错误discard令牌。
- 已修复的导航/焦点：下拉选择新对话后历史与输入为空，没有误回旧会话或复制旧草稿；回旧会话草稿仍保留。采用后Esc和无采用Esc均在下一动画帧后恢复到AI入口，外层设置仍开着。最初观察的BODY焦点问题已解决。
