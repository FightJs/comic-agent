# 风格与流程 Skill

当前实现（2026-11-06）：支持共享流程包安装、项目显式启用、固定版本阶段加载及资料按需读取。它已参与Pi讨论、文本生产及视觉审核的固定输入；不等于原条漫五件套已经完成迁移。

## 操作

1. 在项目库或项目内打开“模型设置”→“风格与流程Skill”。导入JSON或ZIP流程包，查看主规则。安装仅进入共享库，不自动影响任何项目。
2. 进入项目，在同一位置勾选需要的流程，保存本项目选择。每项目最多20项，同一流程仅启用一个版本，可同时组合不同流程。
3. 从当前阶段的“AI助手”发送消息。每次运行按阶段筛选项目启用包，宿主完整加载主规则（主规则总长受限），补充文件通过受控`project_query`工具按需读取（`query=@files`可分页读取包内目录）；不依赖模型猜测是否应加载。
4. 答复下方显示该次使用的流程名称和版本。变更选择只影响下一次运行，旧运行保留原hash和资源；切换同一会话时每次重新声明当前唯一启用版本，历史规则只是参考。

规则用于指导创意、节奏、一致性等建议；它不能授予新权限，不能绕过项目隔离、工具额度、审核和候选采用。当前讨论不修改成品，也不生成图片。主规则中提到的脚本只作为文本资料，安装和读取不会执行它们。外部网页链接不自动下载。

共享包适合放类型/风格规则及通用资料，不要放当前小说正文或密钥。模型只可读取本次项目明确启用并冻结的包；已安装但未启用的包不进入该运行工具范围。密钥使用独立配置包和钥匙串管理，不能放进Skill文件。

## 包格式

JSON示例：

```json
{
  "format": "comic-skill/v1",
  "id": "faithful-fantasy",
  "name": "玄幻 · 一致性优先",
  "version": "1.0",
  "stages": ["outline", "script", "package"],
  "tags": ["玄幻", "一致性"],
  "entrypoint": "SKILL.md",
  "files": {
    "SKILL.md": "# 主规则\n先核对原著证据、人物动机和当前状态，再提出方案。补充见[约束](references/rules.md)。",
    "references/rules.md": "不得为了制造冲突伪造原著事实。"
  }
}
```

ZIP：根目录`manifest.json`包含以上元数据但不包含`files`字段；其余文件按包内相对路径放置。例如`SKILL.md`和`references/rules.md`。不支持直接导入无清单的任意第三方Skill目录，需转换成上述格式；系统不能将宿主专用脚本直接当作已适配工具。

阶段：`setup`、`memory`、`skeleton`、`outline`、`style`、`asset`、`script`、`package`、`image`、`review`。当前页面讨论覆盖前八种；文本生产和视觉审核按各自阶段读取规则，选择标签本身不会增加执行权限。

限制：上传最多10MB；解压文本总量最多8MB、文件最多1500份、单文件最多50万字符、主规则最多3万字符，本次阶段主规则合计最多8万字符。只接受MD/TXT/JSON/PY/JS/MJS/CSV/YAML等文本资源，不执行代码，不支持二进制参考图；实际人物/画风图仍通过项目资产管理。ZIP只在内存中读取，不解压写到任意路径；拒绝绝对路径、上级穿越、符号链接、ZIP重复路径和加密条目。

安装会检查Markdown的包内相对链接；代码示例中的链接不计为操作依赖。可用`../兄弟目录/文件.md`引用同包其他Skill，但最终路径必须在同一包内；缺资料则拒绝安装。外部链接不代表已验证的依赖。

包按内容hash不可变保存。相同id+version不同内容会冲突，需提高版本号；相同内容重复安装返回原版本。项目取消启用不删除历史包，因此旧运行仍可恢复。当前没有物理删除历史版本入口。未保存项目选择在本次应用内保留，关闭重开不会丢失；刷新前需保存。冲突时保留草稿，也可明确放弃草稿读取最新选择。

## 跨包引用与固定依赖

在清单中声明可选依赖，例如 `"dependencies": [{"id": "common-rules", "version": "1.0"}]`，再用 Markdown 链接 `[公共约束](skill://common-rules@1.0/rules/common.md)` 引用。版本必须精确匹配，不支持 latest、网络下载或个人技能目录读取。依赖包可任意顺序安装，但保存项目选择时必须明确勾选全部依赖；缺包、版本不符或目标文件不存在会拒绝保存并保留选择草稿。可按名称、ID或版本搜索定位依赖。AI安装候选也遵守同一规则，不自动安装或启用依赖。

依赖授权以整个包为只读单位，不是逐文件访问控制。运行冻结依赖的内容hash，之后取消项目启用不影响旧运行。其他阶段的依赖标为“引用资料”，其主流程不会自动注入；模型仍可按固定依赖读取包内资料。配置助手和生产所需资料闭包沿相对链接与跨包链接遍历，按hash和路径去重，循环不会无限展开；受1500文件、8万字符限额约束。

跨包地址拒绝上级穿越、绝对路径和查询参数。每包最多1500条去重后的跨包引用边，重复链接不重复占用额度。无依赖的旧包仍省略空dependencies，保持原内容hash；相同ID和版本不可改写。任何脚本仍只是文本，不因依赖声明而执行。

验证入口：`backend/tests/test_skill_dependencies.py`覆盖精确版本、显式选择、冻结读取、循环闭包、安装/配置助手关口及真实Pi SDK调用本机替身读取。独立页面记录见`docs/pi-skill-reference-ui-review.md`；不代表真实供应商质量或五件套完整迁移验收。

## 存储、验证和待完成项

`skill_packages`、`skill_files`与`project_skill_settings`都存入现有SQLite，随整个`data/`目录备份；`agent_inputs`冻结本次实际使用的hash和目录。运行不依赖用户个人`~/.codex/skills`路径，也不读取全局Pi skills。

当前采用宿主明确注入阶段主规则、Pi工具按需读取资源的加载方式，不是开放全局目录和内置文件工具。自定义包安装与加载已接通；计划中的原条漫五件套规则迁移、专属脚本适配、复杂代表格生成与实图验证仍未完成，不能把现有安装器宣称为五件套迁移完成。

自动验证：`backend/tests/test_skills.py`、`test_agent_runtime.py`、`frontend/src/SkillManager.test.tsx`及Node协议测试。真实SDK→替身供应商测试检查主规则与补充资料均到达模型请求；语义质量与真实供应商未验证；生产接线的证据另见文本生产及视觉审核专题。页面独立审核见`docs/pi-skills-ui-review.md`。

## 原条漫五件套首版规则包

`resources/comic-skills/packages/`提供五份自包含JSON，操作及逐项迁移状态见[迁移说明](comic-skills-migration.md)。可通过现有直接导入或AI附加包→安装候选使用，项目启用仍明确保存；不自动安装。当前为5份入口、11份内置MEM与18份参考适配、5份宿主元信息映射，50份资料待审、3份已审仍部分宿主映射、1份部分适配脚本/121份未登记脚本待处理，不能称完整迁移。生成和运行只读仓库包，不依赖个人技能目录。

配置助手现支持直接要求“安装内置五件套”：宿主只读本次冻结的应用规则目录，AI查询后才可提出安装候选；无需附加文件。候选采用不热读新文件，重启后沿用原固定正文。安装与项目启用继续独立确认。当前内置版本1.0.0-pi.4，升级需明确重新选择，旧运行不热改；剩余50份待审资料、3份已审仍部分宿主映射/121份未登记脚本及1份部分适配仍未完成；首项受控只读画幅检查见[操作](frame-plans.md)。
