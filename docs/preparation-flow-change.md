# 前期准备合并与画风串行确认

日期：2026-11-03

## 已实现

- 前期六个独立入口归为理解与记忆、改编与细纲、画风与资产；内部保留六类原记录及版本，不迁移或删除业务数据。
- 保留旧 stage 存储值，映射到新分组；记录各组最后页签，原著搜索/章节、文档草稿继续使用原缓存，切换阶段恢复阅读滚动位置。
- 细纲页可直接打开按话范围生成，默认使用当前选择的细纲。未保存骨架或所选细纲时禁止提交，避免从旧文稿生成。
- 三版画风使用同组预置人物“阿青”和场景“旧院”，每版两张明确标注模拟的样图。卡片可展开，确认准确版本后进入全面资产页，不自动生成。
- 已确认方案在页头、卡片和详情显示编号/版本。未确认或画风版本改变时禁用资产生成，后端也返回409。
- 资产生成任务冻结画风ID、版本、来源；切换画风后旧资产保留并标记，旧审核记录保留但追加需重新确认结论，切回旧画风不会恢复旧审核。
- 旧资产可明确“确认符合当前画风”，建立新的待审核版本。模拟画风派生版本保持模拟来源，不满足正式生产条件。
- 任务执行期间画风改变时，结果仍使用任务提交时的画风引用，页面按旧画风处理。未绑定画风的历史中断任务需重新提交，不能直接重试绕过依赖。

## API

- GET /api/projects/{pid}/style-selection：unconfirmed / confirmed / stale，附所选记录、版本、来源。
- POST 同一路径：确认当前版本，过期版本409。画风确认与正式审核分别记录。
- POST /api/projects/{pid}/records/{rid}/confirm-style：携带资产version，绑定当前画风、创建待审核新版本，冲突409。
- 原 assets 模拟任务入口和图片导入复用既有接口；生成任务冻结 style_reference，新导入资产在画风已确认时绑定该画风。

## 验证

- 38项后端测试通过：包含未确认禁止生成、版本冲突、项目隔离、迟到结果冻结、模拟来源、重新确认审核失效、切换回旧画风、同组三版样例。
- 20项前端测试通过：包括旧六阶段分组映射、细纲选择及未保存输入保护；原150格表格等回归保持通过。
- 生产构建及 git diff --check 通过。
- 独立真实页面验收见 preparation-ui-review.md；审核期间修复了样图标签重叠、已选方案身份不明确两项问题。
