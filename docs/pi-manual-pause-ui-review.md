## 问题（按严重度）

### 已解决（初审重要）MP-01：底稿更新会静默重置打开的暂停讨论与草稿

- 位置：脚本审核→选第1话第1格→讨论并修改选中格→脚本审核AI助手。
- 条件：已有manual_pause运行 `d3ee9a84517e4a009db98a5698308748`，会话 `d7cbf403c70f4456aa4228d0216806db`；固定脚本v1。输入“此意见暂不发送，用于核对冲突后保留。”并勾授权。开发端仅用公开 records PUT 将合成底稿相同正文从v1提升v2。
- 现象：面板刷新后回到“新建讨论”，暂停记录、授权框、未发送意见与共同要求均消失；显示底稿v2。未出现原检查点续接409错误。旧会话服务端是否保留不能抵消当前用户上下文丢失。
- 影响：用户正在处理的暂停与输入被静默替换，无法在原面板核对冲突或继续；违反原数据/未发送意见保留要求。
- 建议：冻结打开讨论的固定输入和会话，版本更新显示明确过期提示；保留未发送草稿和原暂停检查点，不以版本key重挂载整段讨论。
- 实页证据：`stage-1440-conflict.png`；源码辅助：Production.tsx Conversation key含version；Workflow.tsx AgentPanel key含version；AgentPanel scope及草稿键含版本。

### 一般 MP-02：断线续接时同一错误重复显示

- 位置：生产结果抽屉顶部与该任务检查点内。
- 条件：无queued/running且三池为零，开发端保全快照并正常停止临时18766；点击已勾授权的明确续接。
- 现象：同句“无法连接本地服务，请检查服务后重试。当前输入已保留。”在抽屉顶部和检查点内各显示一次。
- 影响：同一故障重复占用纵向空间，弱化任务局部错误定位；不阻碍恢复。
- 建议：轮询断线与当前操作失败合并或去重，保留检查点内可读错误和重试。
- 证据：`production-1440-offline-error.png`。原paused、授权勾选、原要求和旧候选实际保留；服务恢复后原按钮可重试并生成未采用候选。
