# 项目创作偏好

2026-11-06：已实现明确保存、修改和删除，以及讨论/文本生产的固定版本接入。页面独立审核结论与本轮最终验证见 `docs/pi-progress.md`、`docs/pi-preferences-ui-review.md`。

## 使用与生效范围

进入项目后，在“模型设置 → 项目创作偏好”或阶段AI助手的“本项目创作偏好”展开编辑。项目库全局设置不提供跨项目偏好；不会自动从聊天摘取或安装偏好。

可保存风格、节奏、表达习惯等文本，最多6000字符。只有“保存项目偏好”成功后才影响后续新讨论和骨架、细纲、脚本、生图包文本生产。当前明确要求优先；偏好不是原著事实/证据，不配置API密钥、不改变工具权限、生成授权、候选采用或人工审核。原著图谱抽取、系统配置助手不会加载创作偏好，直接图像请求也不会偷偷改写已核对的提示词。

读取最新偏好只更新已保存内容，不覆盖当前输入。版本冲突后可展开最新内容核对，再“保留我的输入”保存，或显式还原。未保存草稿按项目保留在本标签页sessionStorage；浏览器拒绝存储会说明关闭/刷新可能丢稿。识别到常见密钥格式时只留当前临时输入，不写浏览器草稿、不提交偏好，已匹配的旧缓存也不恢复；恢复普通内容后草稿正常保留。这不是通用秘密扫描。没有打开编辑器时不额外请求其API。

“删除已保存偏好”清空当前生效文本并推进版本。若编辑框有尚未保存的新内容，删除仍保留这份输入，并明确提示它尚未生效。删除不是“让模型忘记所有历史”：已发给模型的对话、原运行输入快照以及已保存结果不会自动擦除。

## 固定版本与续接

`freeze_context`将`{revision,text}`保存到每次非setup运行的输入快照，讨论编译请求及生产system/context明确区分偏好与事实/授权。历史讨论可展开本次偏好版本与原文；旧运行没有此字段时不伪造历史版本。

偏好更新或删除不会改写在途任务和旧候选的固定快照；新运行读取新版本。明确续接原讨论检查点时会再核对当前偏好revision，不匹配则拒绝续接旧偏好，须结束暂停后重新讨论。原本无偏好的旧讨论按v0匹配，已有偏好不会被无记录的旧续接默默覆盖。

偏好不是来源证据，不改变原来的mock继承。它也不替代原著版本、Skill版本与审核关口。

## API与保存

```
GET /api/projects/{pid}/preferences
PUT /api/projects/{pid}/preferences
{"expected_revision":0,"text":"人物一致性优先，台词简洁。"}
DELETE /api/projects/{pid}/preferences
{"expected_revision":1}
```

字段严格校验，拒绝多余字段及非整数修订。PUT/DELETE在SQLite事务中检查版本，过期409、未知项目404，错误不回显输入正文。检测到常见密钥格式则拒绝保存，密钥仍应通过模型配置管理；这不是通用秘密扫描保证。

存储为`project_preferences(project_id,revision,text)`，每项目独立。空偏好默认v0；DELETE即使当前已空也推进版本，阻止删除前旧草稿复活；同文PUT可保持幂等。删除保留空行和新revision，不将修订归零。运行的旧偏好保留在对应不可变输入快照中，随整个data目录备份。

## 验证限制

自动化包含CAS与删除屏障、项目隔离、重启保存、setup排除、实际Pi SDK新讨论加载/删除后新请求/其他项目不泄漏、实际图谱调用不含创作偏好、三次文本生产分别冻结v1/v2/v3、偏好变更阻止旧检查点续接。均使用合成文本、本机替身和假凭据，没有真实供应商或真实小说质量验证。

实际SDK输入证明不等于真实模型会在所有复杂提示中始终正确服从风格优先级，更不证明真实长篇语义质量或压缩保真；这些仍按原Pi实施计划继续验收。
