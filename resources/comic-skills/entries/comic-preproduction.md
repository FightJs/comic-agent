# 条漫前期协调（工作台移植）

适用于配置流程、确认输入、改编筹备、阶段衔接与恢复范围核对；不是启动旧外部生产器的指令。先读[工作台合同](references/workbench.md)。

1. 先确认本次新任务/继续讨论/恢复的真实范围、当前项目和阶段，以及实际附加原著、脚本、画风、资产和方案版本。恢复沿用旧输入、采用记录和未知调用；新任务不擅自追索无关旧工程。输入不全先指出准确缺项，不要求不懂技术的用户填写宿主JSON或寻找个人电脑路径。
2. 配置阶段核对脱敏用途、所附配置包和已安装流程。只提出包应用、共享安装、项目启用候选，安装不等于启用，保存不等于连接验证。密钥只经配置包，不要求聊天粘贴；规则更新不热改旧运行。
3. 理解/改编阶段先查本次冻结原著和已发布摘要；区分原著事实、改编选择、视觉推断与未知。需要修改图谱、骨架、细纲或脚本时用当前候选接口，说明准确影响范围，不从普通答复直接写业务结果。
4. 资产阶段锁定人物身份、当前衣装、场景与批准画风。镜头阶段保持源格身份，决定本格动作、机位、裁切、必要背景与实际参考。逐格包须把关键画面事实与批准约束落到真实绘图提示词，不能只有元数据。
5. 先在用户已授权范围用代表性复杂格核对完整输入；不为局部修改复制整话、不重新生成未变化资料。真实前图像素依赖与普通剧情顺序区分；未实现批量编排时给出计划，不宣称已连续执行。
6. 所有候选、采用、图片及审核沿用项目现有账本与固定版本。技术就绪、结构合法、模型建议与用户决定分别记录；只有真实业务状态可支持已执行/完成表述。未决调用、缺图或未审图不得冒充全批完成。

交接说明应包含：实际已读范围、当前固定输入、已完成与待采用候选、真实缺项及受影响格、未知调用与下一步可执行操作。不要凭空添加统一半话停点、额外用户审批或旧宿主路径要求；宿主既有关口和明确用户要求始终生效。
