## 实际验证

1. 脚本表选第1话第1格v1→讨论并修改。资料自动绑定当前格，无需再次勾选，展开资料可见固定v1；正常问题经真实SDK查询目录后流式回复，最终显示回复完成及“将此回复加入生成方案”。回复未完成时曾实际观察取消按钮，尚无加入按钮；本轮未执行真实取消。
2. 讨论结束与点击“加入方案”后分别查询任务列表，均为空。加入后方案出现原回复、引用1条以及尚未生成提示；再点击“按方案生成候选”才建立任务。
3. 成功任务回执实际包含agent_discussions的run_id、session_id、refs、原回复及source，引用格版本为v1。生成只增加候选，原脚本仍v1；结果页原稿与候选对照清晰，明确采用后脚本推进v2，身份未改。
4. 采用后关闭并重新进入v2讨论：新会话、空方案、底稿v2，不显示v1会话为当前讨论。可通过显式“查看本组修改结果”查看已采用历史，关闭结果回到当前讨论，再关闭外层均成功。
5. 通过安全API构造同格旧模拟讨论，页面历史区域实际展开，明确“历史讨论只读，不会加入当前生成方案”，模拟助手标签保留，没有加入方案按钮，当前正式方案为空。
6. 生图包选格→讨论，自动绑定包而非脚本，包会话独立；完成回复→加入→生成候选路径实际走通。修复后仅更新分镜段，原人工完整提示词保留；结果页明确说明覆盖模式下分段不会自动合成。明确采用后API核对包v2、分镜更新、完整prompt保持原值、prompt_mode=override。
7. 临时拦截发送请求返回503，表单内出现可读红色alert，未发送文字保留，原方案/引用保留；路由已撤除。该项在后台修复重启前实测，相关前端失败逻辑未改，不冒充修复后的重复验证。
8. Esc关闭后焦点实际恢复至“讨论并修改选中格”；显式结果与外层关闭按钮均已点击。表格、讨论、方案和结果在两种桌面窗口均可滚动，关闭按钮固定，无观察到横向溢出。

## 已发现并关闭的重要问题

- **旧结果抽屉自动恢复并挡住当前版本讨论。** 初次采用脚本v2后，重开讨论自动显示旧嵌套结果；点击结果关闭按钮遭外层header拦截，Esc又关闭全部。主agent改为结果展开只保留在本次挂载内存，历史组保留显式入口。已重新走v1→生成→采用v2→关闭→重开，确认只打开当前讨论；显式历史结果打开和两层分别关闭均成功。证据：`/tmp/pi-batch-reopen-fixed-1280.png`。
- **包分段改写覆盖legacy人工完整prompt。** 初次包生成只返回分镜patch，却把完整人工提示词替换为分镜段。主agent统一legacy覆盖模式保护并增加说明。重启后重新生成、查看及采用，确认完整prompt保留、shot_prompt更新、override模式正确。证据：`/tmp/pi-batch-package-prompt-fixed-1280.png`及采用后只读API核对。

以上问题已经实际复审解决，最终没有未解决的阻断或重要问题。
