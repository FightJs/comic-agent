# 工作区框架与内容密度 · 2026-11-03

## 目标与改动

响应1146×709桌面窗口反馈：脚本表格起点过低、不同阶段缺少流程标识，切换全书前期准备/批次制作时壳层跳动。

采用共用框架而非逐页缩放：204px侧栏、52px顶栏、20px横向内距；各阶段保留同一紧凑标题、流程位置和副说明，制作话格定位并入页头。普通阅读/编辑页保留各自业务结构；脚本、生图包和桌面图片工作区按剩余高度分配核心区域。表格保留完整字段、固定表头与话格，内部双向滚动；图片三栏内部滚动，画布按实际容器调整尺寸。没有改变数据、审核、版本、生成、保存和下载含义。

`workspace-frame.css` 在基础样式后统一定义框架；App/Production添加必要的布局容器，移除图片和生图包隐藏标题的特例；AnnotationCanvas的ResizeObserver读取容器实际宽高。

### 一般待修建议

- U1：只读GET延迟时，生产条件显示“0项待完成”，条件尚未读取，可能短暂误导。建议改为正在读取或完成后显示数量。截图 `frame-review-loading-1146.png`。
- U2：图片GET 503时，错误提示下仍显示生成/导入图片的空态，可能将失败误解成没有图片。建议区分暂时无法读取，并提供重试。截图 `frame-review-error-1146.png`。

两项为既有状态文案，不阻断本轮交付；本轮未修改相关业务逻辑。
