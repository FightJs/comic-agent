# 图谱代码审查

**当前结论：限定复审范围内没有未关闭的重要问题。** 此前发现及后续边界均已修复；以下历史记录保留审查轨迹。最终两项时间边界已核验：同名状态合并先限制来源披露时间，细纲证据同时核对精确引用及所属话号，并有对应回归。后端报告完整套件 79 项通过（图谱 41 项）；本次未重复运行。真实供应商质量和浏览器验收不在本次复审结论内。

范围：`docs/graph/implementation.md` 所列图谱后端、前端与集成；仅静态审查当前源码，未复跑现有测试，也未连接真实模型或 MinerU。以下是可从代码直接推导的待修重要问题，行号以审查时源码为准。

1. **细纲重新抽取会丢失人工关系及其锁定字段。** `backend/graph_engine.py:377-381` 对节点调用 `protected_merge`，但关系仅从新抽取图中过滤后直接覆盖 `state['adaptation']`。例如用户新增 A→B 手工关系，保存当前细纲并等待抽取后，该关系消失；对现有关系的人工修改也会被新结果覆盖，且不会产生冲突。原著重抽取的无细纲分支 `:361` 虽保护匹配关系，但同样丢弃未出现在抽取结果中的人工新增关系。应保留未删除人工关系，合并匹配关系的锁定字段，并验证端点及删除抑制。

2. **未被改编提及的原著实体从改编完整图消失。** `backend/graph_engine.py:363-381` 将改编层设为细纲抽取的节点列表，未将未提及的原著节点加入并标注 `in_adaptation=false`。例如原著有甲乙，细纲仅出现甲，改编图里乙无法搜索、查看或区分为未采用。契约要求“未提及仅未采用”、隐藏节点可搜索和完整图不截断；应保留其身份及未采用状态，并谨慎处理章节到话的时间映射。

3. **同名人物可能未经证据被自动合并。** `backend/graph_engine.py:240-243` 将缺省 `identity_key` 设为名字，以项目、文档、类型和该值生成节点 ID；`:295-297` 对同 ID 的抽取结果无条件合并。模型 schema `:454` 将 `identity_key` 写为可选，因此同名同类型的两个人在模型未给键时会合并，即使没有任何同一身份证据。需避免按名称自动确定同一身份，并以证据约束跨块整理。

4. **不同原著任务可逆序覆盖较新的图。** `backend/graph_engine.py:85-90` 仅在同一文档/解析版本去重；`:340-354` 完成时只检查该文档自己的版本，随后直接替换项目原著层。先导入 A 再导入 B，如果 B 先完成、A 后完成，A 会覆盖 B 的已发布图；两任务原子提交也不能阻止旧任务迟到。应定义项目级当前源及代次，完成时核对，或在切换来源时将旧任务标记 superseded。

5. **本地 MinerU 可漏页后发布。** `backend/graph_mineru.py:21-28` 本地接口仅拼接返回的 Markdown 并检查非空，未使用 `expected_pages` 检查覆盖；Cloud 分支才在 `:69-70` 检查页码。多页 PDF 的本地服务若只返回部分正文，将被视为完整解析并触发正式抽取。应取得并核验逐页结果；无法证明覆盖时应阻止发布并说明原因。

以上未涵盖真实供应商抽取质量、浏览器视觉验收或完整性能实测，不应据此声称这些项已通过。

## 修复后限定范围复审（当前源码）

五项原问题均有对应修复和回归用例：人工关系保留、未采用节点保留、缺省身份键隔离、项目级原著代次、本地页覆盖校验。明确清空后原著重抽取保持空改编层；缺失或错误偏移时仅对唯一精确引文回填；取消后的正常响应会先记录用量。未复跑测试套件或验证真实供应商。

仍有重要边界问题：

1. **取消/替代任务可能被迟到的异常覆盖为失败。** `backend/graph_engine.py:551-561` 异常处理未检查任务当前状态。第三次请求执行中用户取消（或任务被新来源替代），随后供应商返回含 usage 的无效 JSON 或发生网络异常，`:561` 将 `cancelled`/`superseded` 改写为 `failed`。应在事务内检查终态，保留状态并对已收到 usage 持久记录；现有取消测试仅覆盖有效 JSON。
2. **模型提供相同 identity_key 仍可无证据自动合并。** `backend/graph_engine.py:265-269, 321-323` 用模型自由填写的相同 identity_key 跨块生成同 ID，后续 combine 直接合并，而不是经过有同一身份证据的整理。两位同名人物若模型都填写相同 key，会误合并；回归测试仅覆盖 key 缺省。应隔离分块身份，把跨块归一交给带证据的整理。
3. **无法取得 PDF 页数时页覆盖检查失效。** `backend/graph_engine.py:440-446` 捕获 PdfReader 失败并保留 `expected_pages=0`，而 `backend/graph_mineru.py:33,85` 仅在页数非零时验证覆盖。此时解析器只返回部分页也可以发布。应在不能确认原 PDF 页数时拒绝将 OCR 结果作为完整正文。

## 最终修复限定复审

- 迟到异常覆盖终态：已修复，异常处理检查任务状态；新增第三次请求取消后无效 JSON 和用量回归。
- 跨块模型 identity_key 自动合并：已修复，ID 加入分块范围；新增相同 key 同名人物回归。跨块合并现走带引用和原因的整理。
- PDF 页数未知绕过覆盖检查：已修复，页数不可核验时停止 OCR；新增未知页数回归。
- 显式清空、唯一精确引文、已接收失败响应的用量：代码及对应测试已检查。
- 恢复资产依赖 409、关系字段解锁、显式资产重绑保留不可变版本、冲突携带证据：已检查代码；前三项有定向回归。
- **仍有重要问题：实体合并后的时间投影泄露身份。** `backend/graph_engine.py:363-388` 仅将别名时间提升至身份揭示时刻，却直接将另一身份的 label、summary、attributes 历史和状态按原时间并入目标，并将其边立即重定向。例：甲在第 1 章出现、乙在第 2 章出现、第 3 章才揭示二者同一身份；查询第 2 章可能将乙的事实、状态或关系归到甲，从而提前暴露身份。跨身份转移内容需要以揭示时间和原事实时间的较晚者投影，并保留相应历史。

此为静态复审；本审查未重复运行测试或连接真实供应商。后端报告称完整套件 76 项通过。

## 身份揭示时间修复复审

被合并实体快照、证据和历史事实按披露时间限流，并在较早时间视图恢复实体及关系端点；新增三章替身回归覆盖合并前事实与关系隔离。仍有一处状态边界：`backend/graph_engine.py:384-385` 合并同名状态时直接对目标和来源状态的 `known_from` 取最小值。来源状态早于目标状态、身份在更晚章节才揭示时，目标状态可能提前出现在目标身份下。应先对来源时间取 `max(known_from, disclosure)`，再与目标状态时间取最小值，并加入回归。

## 最后两项时间边界复核

同名状态的来源时间现先取 `max(原时间, disclosure)` 再与目标时间比较（`backend/graph_engine.py:385`），对应四章回归覆盖。细纲证据现检查所属话号和不可变版本中的精确文本（`backend/graph_store.py:44-52`），对应错误话号拒绝及正确话号通过回归。此前同名状态问题关闭。

## 缺失锁节点限定复审（待修）

自动节点带人工锁且抽取缺失时，两条发布分支均保留节点；接受 `__presence` 的删除会删除关联边并记录抑制。仍有重要问题：缺失产生冲突后，如果后续抽取重新出现节点，旧缺席冲突不会清理；接受旧冲突会删除已重新出现的节点并永久抑制（`backend/graph_engine.py:404-411,438-439,465-467`；`backend/graph_store.py:238-242`）。应在重现时移除过期缺席冲突或拒绝旧选择，覆盖缺席→重现→处理路径。

## 缺席冲突过期修复复核

每次发布先清除该来源的旧缺席冲突，再按当前结果生成必要冲突；其他来源及普通字段冲突保留。原著与细纲两条回归覆盖缺失后重现、旧冲突 ID 拒绝、节点和人工锁保留。此前缺席冲突过期问题关闭。此次未重复运行完整套件，后端完整套件正在运行。
